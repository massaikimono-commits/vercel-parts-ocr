# Independent OCR architecture plan (design only)

Date: 2026-10-03. Source revision inspected: `a6e84cda`. This file contains no source photographs, OCR text, annotations, ground-truth field values, or per-image coordinates. It does not authorize a runtime switch.

## Observed code boundaries

- `p5-token-evidence.mjs` already validates TSV/blocks and preserves token boxes; retain this as a shared input contract.
- `p5-token-grid-core.mjs` and `p5-semantic-candidates.mjs` cluster all page words into horizontal rows and assign words to the nearest semantic header center. A missing header, split header, duplicate `単価`, a wide name cell, or nonuniform rows can misassign an entire row. The partial-header lattice still assumes four ordered positions.
- A20/A22 recognize pre-cut cells from expected fractional geometry; A22 measures rules but maps them back to an expected array. This cannot establish columns on arbitrary table widths/order or pages with two slips.
- `document-regions.mjs` P6 relies on yellow/neutral color components and a convex quad. A bad region causes a recognition-scope change. Treat it as an optional observation, never a required crop, until geometry checks and a full-page fallback pass.
- `orientedCanvas` uses aspect ratio to pick a single 90-degree rotation. Recognition and geometry need an explicit orientation boundary and coordinate transform.

## Shared representation and invariants

Carry an immutable `PageEvidence` with image width/height, orientation transform and inverse, paper/table hypotheses, text boxes with raw confidence/source, measured rules, and provenance for every proposed cell. A row has a stable geometry ID and explicit `present`, `missing`, or `unreadable` state per field. An empty OCR string from a visible cell is `unreadable`; a column absent from a confidently classified layout is `missing`. Preserve empty row slots until row association finishes. A strike-through is recorded as visual evidence requiring review; it cannot silently delete a row because cancellation semantics are unresolved. Return `manualReviewRequired: true`; no candidate here may auto-confirm.

Use a document-family classifier only from generic observed paper/header evidence. Context resolves the overloaded header `単価`: yellow delivery slip with `標準価格` means `標準価格 → retail`, `単価 → cost`; white parts list with `数量` and `単価` but no purchase-price header means `単価 → retail`, `cost → missing`. The public row value for this absent white cost column is the existing empty string, while its internal state is `missing`; a visible but unreadable cost cell also exports an empty string but carries an `unreadable` review reason. If both interpretations remain plausible, emit both labeled hypotheses or abstain. Never infer price meaning from OCR values, expected row count, filename, or supplier answer dictionary. Header aliases may help semantics but cannot be the sole geometry source.

## Candidate R: row-first image geometry, then field recognition

1. Normalize EXIF orientation and form a bounded-resolution grayscale/color page. Estimate table zones from the intersection of long line segments, horizontal ink projection, whitespace gutters, and text-box density. Use color only as weak evidence. Keep full-page evidence if a region cannot be trusted.
2. Derive row bands from measured horizontal rules where present; otherwise use projection valleys and token baselines. Allow different row heights and wrapped names. Merge a wrapped text line with an adjacent numeric-bearing row only when its horizontal span and baseline continuity support the link. Do not use a fixed pitch or expected row count.
3. Within each row band, derive column boundaries from vertical rules or repeated whitespace gutters across several rows. Associate header phrases to these boundaries by box overlap and monotone alignment. Leave a column unlabeled when its header evidence is ambiguous.
4. Perform OCR on complete bounded cells using existing recognizer interfaces, retaining raw output and crop quality. Use page tokens only as a cross-check, not to create cell boundaries. If a crop loses ink, retry once with a rule-aware expanded boundary; retain both outcomes and mark disagreement.

Distinct failure mode tested: whether geometry-first cells preserve associations when page OCR fragments Japanese headers or joins adjacent fields. It must abstain when rules and projection disagree, a band is too narrow for legible text, or multiple table zones overlap.

## Candidate G: document graph from page tokens and visual rules

1. Start from full-page token boxes. Form phrase nodes by adjacent tokens on the same line and candidate line nodes using vertical overlap, not a single global center tolerance. Preserve competing phrase segmentations.
2. Add horizontal/vertical rule nodes and whitespace-gutter edges. Infer one or more table components from local repetition of rows and aligned x intervals. This enables a page with two slips without allowing background text to become a row merely because it is below a header.
3. Solve header-to-column assignment jointly with row-to-cell assignment. Allow partial headers, arbitrary column order, extra non-target columns, and missing cost column. Use a monotone layout constraint within each table component, token-box overlap with column intervals, numeric/text class, and continuity across neighboring rows. A header match is evidence, not a mandatory gate. Score all hypotheses with these document-internal measurements only.
4. Keep the top two hypotheses if their document-internal scores are close; mark conflicting fields for review. A cell can have multiple source tokens but each token has at most one winning cell assignment. Never use nearest header center as the only assignment feature.

Distinct failure mode tested: whether holistic association recovers rows when line/rule segmentation is weak but page OCR boxes remain useful. It must abstain on unsupported inferred columns, conflicting repeated headers, or unstable table membership.

## Candidate O: orientation and recognition boundary

This is an independent acquisition branch that can feed either R or G; do not silently combine it into the winning branch after evaluation. EXIF-normalize, render 0/90/180/270 thumbnails under the same pixel cap, and acquire OCR boxes uniformly. Rank rotations by a fixed document-internal score: sum over in-bounds text observations of `OCR confidence × min(12, Unicode letter/digit count)`, multiplied by `1 + fraction of observations consistent with horizontal text lines`. The cap prevents one giant line from dominating. Define horizontal consistency by the observation box aspect and same-baseline neighbors, with geometric tolerances proportional to median observed text height. The confidence term is compared only among rotations from the same engine. Retain the top two for full-resolution recognition; if fewer than two have usable evidence, preserve only the usable one, and if three or four scores are within one median observation contribution of the best, abstain rather than choose. Record forward/inverse transforms and reject a hypothesis whose boxes map outside the original image. Use one page-level pass plus a bounded targeted pass on low-quality cells. Preserve unaltered raw OCR beside normalized values. Freeze this formula and tie rule on synthetic cardinal rotations before real diagnostic execution. This directly tests the current aspect-ratio rotation assumption and the recognition/crop boundary without changing row selection thresholds.

## Candidate V: system OCR acquisition boundary

If the local capability probe confirms usable Apple Vision text observations, preregister `V_APPLE_VISION` as a separate input engine for the same frozen G graph. This is an engine variant, not a provider ensemble. Convert Vision's normalized bottom-left boxes to the shared top-left pixel coordinates after the explicit orientation transform; test forward/inverse mapping with synthetic labeled rectangles. Tag each observation with `source`, `granularity` (`line`, `word`, or `char`), raw text, confidence when supplied, and bounds. Use true word/character range boxes only when Vision supplies them; do not fabricate word boxes from a line. The graph must accept line-level evidence with lower precision or abstain. Compare G with Tesseract and G with Vision under the same synthetic layouts and report box coverage, source granularity, errors, latency, and peak memory. Vision is offline/system-local; no external account or network transfer is needed. If the API is unavailable or boxes are inadequate, record an explicit unsupported result rather than substituting a different engine.

## Predeclared comparison and limits

- Implement R and G as separate variants sharing only acquisition contracts, image transforms, field semantics, and result schema. O and V are explicit acquisition variants if the time budget and capability probe permit; no late opportunistic combinations.
- Unit and synthetic development cases may validate mechanics: translated and resized tables; variable row height; split/occluded headers; arbitrary column order and an extra numeric column; white `単価` without cost; yellow `標準価格` plus `単価`; two page components; 90/180/270 rotation; perspective, contrast, glare, background text, and empty/struck cells. Generate labels from the synthetic source itself. These are invariance checks, not a claim of accuracy on unknown photographs.
- Choose implementation readiness only from fixed preregistered structural invariants on synthetic/development inputs: valid coordinate round trip, no cross-document token assignment, stable row identity under resize/rotation, correct documented semantic mapping, retained missing/unreadable distinction, no silent row compaction, deterministic output, and zero auto-confirm. Freeze source/config/model hashes and the decision rule before any diagnostic scorer runs.
- After freeze, execute the unchanged local runner on all 15 real originals and apply the existing separate diagnostic scorer exactly once to the currently reconciled diagnostic 60/15 annotations. Report all fields, false/missed rows, timeouts, and latency for every predeclared candidate, including negative results. The requested formal 54/9 and historical white identity remain HOLD; diagnostic 60/15 must not be described as formal evidence. Do not change code or thresholds in response to those scores.
- Treat a candidate as eligible for a later adoption proposal only if it produces traceable source boxes/crops, no unexpected row deletion, no wrong auto-confirm, acceptable runtime/memory, and a complete reproducible diagnostic report. If no candidate meets those conditions, keep HOLD. Diagnostic score may describe performance after freeze, but cannot select parameters or motivate a second tuned submission in this run.

## Resource and privacy boundary

Process an image at bounded pixel size, reuse one OCR worker, cap region/orientation hypotheses and cell retries, and record peak memory and per-stage wall time on a representative mobile browser before adoption. Proposed guardrails for the experiment: at most two table components, two full-resolution orientations, one page pass plus one targeted cell retry, and a per-image timeout. Return a reasoned abstention on budget exhaustion. Keep image bytes, text, tokens, crops, and diagnostic scoring files private; publish only aggregate sanitized measurements and source hashes. No network OCR, credentials, DB changes, production deployment, or formal-set mutation.
