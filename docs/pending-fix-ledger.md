# ICB 保留修正台帳

この台帳は、現時点では実装しない修正を「削除・忘却」せず管理するためのものです。
Netlify 本番が再デプロイ可能になった時点で、**全件一覧をユーザーへ提示し、反映 / 継続保留 / 廃止を確認してから**本番対応します。

## 保留修正 #001 — 法定3ヶ月点検対応

- **項目名:** 法定3ヶ月点検対応
- **状態:** 保留
- **保留理由:** `legal_3m` の追加には本体 Supabase DB の `inspection_schedule_type` CHECK 制約変更が必要。現在 Netlify 本番を再デプロイできないため、稼働中の Netlify コードと新DB仕様の不整合を避ける。
- **解除条件:** Netlify 本番が再デプロイ可能になること。
- **解除後に実施する内容:**
  1. 本体 Supabase DB で `legal_3m` を許可
  2. 予定登録画面へ「法定3ヶ月点検」を追加
  3. 必要な編集画面等にも同じ点検区分を追加
  4. 日報の入庫要因「（ ）」欄へ黒文字で `3` を印字
  5. main / Netlify 本番コードとDB仕様を整合
  6. 既存データへの影響確認
  7. 本番テスト
- **関連するDB変更:** `work_orders.inspection_schedule_type` 等の CHECK 制約に `legal_3m` を追加。関連テーブル/関数にも同制約があれば同時確認。
- **関連する画面・機能:** 予定登録、必要な予定編集、日報印刷、点検区分を参照する関連機能。
- **本番反映時の確認事項:** 稼働中コードとの互換性、既存データ、登録/編集/日報表示、main と Netlify の同時整合、回帰テスト。
- **最終仕様:** DB値=`legal_3m` / 表示名=「法定3ヶ月点検」 / 日報コード=`3`


## 保留修正 #002 — 来社「作業待ち」対応

- **項目名:** 来社「作業待ち」
- **状態:** 保留
- **保留理由:** 現在の本体DBには「来社＋作業待ち」を本来の意味で永続保存・再取得する専用項目が存在しない。既存の備考・status・work status・delivery_completed・checked_in_at・stay_reason 等は別用途のため流用しない。専用のDB対応なしでは、再読込後も正確に判定できない。
- **解除条件:** Netlify 本番が再デプロイ可能になり、DB変更と本番コードを同時に整合できること。
- **解除後に実施する内容:**
  1. 「作業待ち」を明示保存できるDB設計を確定して本体DBへ追加
  2. 来社予約の納車予定選択部へ「作業待ち」を追加（来社のみ）
  3. 予定編集でも同じ値を登録・変更・解除可能にする
  4. 日報で通常来社は「来社」、作業待ちは「来社待ち」を車番左側へ表示
  5. 作業待ち時は日報の納期欄を空欄にする
  6. 来社＋作業待ちをトップ・日別・日報・その他滞留一覧・滞留台数から除外
  7. 通常来社は従来どおり滞留開始対象であることを回帰確認
  8. main / Netlify 本番とDBを同時に整合して本番テスト
- **関連するDB変更:** 来社「作業待ち」を専用の意味として保存できる列または同等の正式フィールドと、その制約・RPC入出力・必要なインデックス等。既存別用途フィールドへの流用は禁止。
- **関連する画面・機能:** 予定登録、予定編集、日報、トップページ滞留、日別滞留、その他滞留一覧・滞留台数、共通滞留判定。
- **本番反映時の確認事項:** 来社以外では選択不可、再読込後も作業待ちを保持、納期空欄、納車予定へ誤追加しない、全滞留表示/集計から除外、通常来社への影響なし、既存データ互換性。
- **最終仕様:** 来社＋作業待ち = お客様がその場で作業完了を待つ / 滞留対象外 / 通常納車予定なし / 日報は「来社待ち」。


## 保留修正 #003 — 来社以外の時間重複警告を停止

- **項目名:**  exact-time 重複警告を「来社 × 来社」のみに限定
- **状態:** 保留
- **保留理由:** 現在の本体 Supabase DB の `schedule_slot_check_v2` は、時間指定（exact）の場合、同じ `entry_type` 同士すべてで重複警告を出す実装になっている。確定仕様は「重複警告は時間指定の来社 × 来社だけ。引取 / 納車 / 出張の時間指定同士は警告しない。A中 / 午後 / 午前中 / 午後中 / 中など幅指定は重複警告しない」だが、修正には本体DB関数の変更が必要。
- **解除条件:** Netlify 本番が再デプロイ可能になり、DB関数と本番コードを同時に整合できること。
- **解除後に実施する内容:**
  1. `schedule_slot_check_v2` の重複判定を exact の `customer_visit` 同士だけに限定
  2. 引取 / 納車 / 出張の exact 同士では重複警告を出さない
  3. broad-time（A中 / 午後 / 午前中 / 午後中 / 中）では重複警告を出さない
  4. `schedule_time_availability`、新規登録、変更登録の呼び出し結果を回帰確認
  5. main / Netlify 本番とDBを同時に整合して本番テスト
- **関連するDB変更:** `public.schedule_slot_check_v2` および関連RPCの整合確認。
- **関連する画面・機能:** 予定登録、予定変更、空き状況表示、重複警告。
- **本番反映時の確認事項:** 来社 exact 重複だけ警告、その他 exact は許可、broad-time は警告なし、既存上限・営業時間・休業日チェックは維持。
- **最終仕様:** 重複警告 = 「時間指定の来社 × 来社」のみ。
